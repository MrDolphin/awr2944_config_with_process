# V0.4.64 IMU/雷达固定延迟扫描

## 阶段目的

在 V0.4.63 的时间单位归一化和固定延迟修正基础上，扫描多个可能的 IMU/雷达时钟偏差，检查哪些延迟仍能覆盖全部雷达 frame，并量化延迟选择对插值姿态的影响。

## 扫描设置

- 延迟修正：`-10 ms、-5 ms、0 ms、+5 ms、+10 ms`；
- 原始 IMU 单位：毫秒；
- 最大允许 IMU 源间隔：0.06 s；
- 参考延迟：+5 ms；
- 雷达 frame：5 个，时间范围 0.010～0.090 s。

## 结果

| 指标 | 结果 |
|---|---:|
| 扫描延迟数 | 5 |
| 通过质量门的延迟数 | 5 |
| 通过延迟范围 | -10～+10 ms |
| 相对参考最大 roll 差异 | 0.240000° |
| 相对参考最大 pitch 差异 | 0.150000° |
| 相对参考最大 yaw 差异 | 0.300000° |

## 如何分析

- [latency_scan.csv](../simulation/hardware/awr2944pev/v04_64_latency_scan/synthetic_run/latency_scan.csv) 记录每个延迟的覆盖和质量门；
- `latency_pose_difference.csv` 记录每个 frame 相对参考延迟的 roll/pitch/yaw 插值差异；
- 如果某个延迟导致 `coverage_ok=false`，说明 IMU 数据无法覆盖雷达 frame，不应继续补偿；
- 如果覆盖通过但姿态差异很大，说明时间同步误差会直接影响点云姿态解释，需要外部同步或延迟标定。

## 结论

在本次合成轨迹中，±10 ms 扫描范围都通过时间覆盖门；相对 +5 ms 参考，最大姿态差异为 roll 0.24°、pitch 0.15°、yaw 0.30°。这只是给定轨迹斜率下的时间敏感性，不是实船固定延迟测量结果。

## 证据边界

当前 `source_is_hardware_imu=false`。真实系统应使用同步脉冲、雷达触发、IMU 设备日志或已知运动事件测量固定延迟，再用扫描结果选择可信区间；不能把“某个延迟通过仿真质量门”当作硬件延迟已经确定。
