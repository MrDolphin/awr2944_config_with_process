# 人工角反射器雷达—相机标定工作台设计

## 目标与范围

为固定安装的 AWR2944P 雷达和 DW800 相机增加一个网页标定工作台。操作者将角反射器静止放在场地中，分别选择同一目标的雷达原始点和相机像素中心。系统把它们冻结为一条可追溯的 3D—2D 对应样本，区分拟合样本和独立验证样本，并在 PC 上生成可部署的雷达—相机外参文件。

第一版不要求 AprilTag、ChArUco 或自动目标识别。角反射器是唯一标靶。相机内参必须已通过独立流程获得，手动外参工作台不以猜测的视场角代替真实内参。

不在本功能范围内：云台运动、雷达配置自动调整、角反射器自动关联、相机内参求解、自动加载或部署新标定结果。

## 物理安装差记录

工作台新增“雷达—相机安装测量”区，用于记录可用卷尺、直尺和水平尺得到的机械差值。它为求解结果提供合理性检查和现场可追溯性，不替代角反样本求出的外参，也不允许单独凭测量值开启投影。

表单记录的量是**相机光心相对于雷达天线相位中心**，在雷达本地物理轴中表示：`dx_m` 为相机向右为正，`dy_m` 为相机向前为正，`dz_m` 为相机向上为正；另记录相机相对雷达的机械 yaw、pitch、roll（单位为度）及测量说明。

例如，若雷达相位中心比相机光心高 10 cm，且两者没有左右、前后差，则操作者填写：

```text
dx_m = 0.00
dy_m = 0.00
dz_m = -0.10
```

这表示“相机在雷达下方 0.10 m”。若相机比雷达高 10 cm，则填写 `dz_m = +0.10`。使用前必须通过将角反上移、下移的已知距离，验证雷达原始点的 `z` 正方向与上述本地物理轴一致；不一致时在会话中明确记录轴映射，不能靠翻转输入符号猜测。

测量基准必须是雷达相位中心和相机光心的近似位置，而不是外壳边缘、三脚架或镜头前缘。建议用垂线投影和尺子分别量左右、前后、上下三项，并记录测量不确定度。小型安装结构推荐记录到 5 mm；不能准确测量时保留为空，并由求解后的独立验证判断结果。

求解使用的投影公式为 `p_camera = R_radar_to_camera * p_radar + t_radar_to_camera`。其中 JSON 的 `translation_m` 是雷达原点在相机坐标系的坐标，不能直接与表单的 `dx/dy/dz` 相比。求解器会额外输出换算后的 `camera_center_in_radar_m = -R^T * t`，再与输入的物理安装测量比较并显示三轴残差；残差只作报警和复核，不自动拒绝或修改标定。

## 方案比较

### 方案 A：冻结快照上的双侧人工选点（采用）

操作者先冻结一组已经匹配的雷达帧和相机帧，在 PPI 选择原始雷达点，再在相机图像上选择角反中心，保存为样本。

优点是对室内多径、墙面杂波和稀疏点云最可控；每一个输入都可显示、删除和复核。缺点是需要人工点击。

### 方案 B：图像点击后自动匹配最近雷达点

速度较快，但相机与雷达没有标定前不能可靠地定义“最近”，室内杂点会造成错误对应，因此不用于第一版。

### 方案 C：AprilTag 或 ChArUco 自动提取图像中心

可减少视觉侧人工点击，ChArUco 还适合相机内参标定。但需额外打印标靶、检测库和严格的角反—标记刚性几何关系；小角反与大纸质标记的中心偏移也会引入系统误差。作为后续增强功能，不阻塞第一版。

## 操作者工作流

1. 在网页中打开“人工标定”工作台。仅当当前相机同步状态为 `matched` 且画面已载入时，允许创建快照。
2. 点击“冻结当前帧”。浏览器保存不可变的雷达帧、相机帧标识、相机 URL、雷达—相机偏移、相机原始图像尺寸、雷达点列表和采集时刻。
3. 在冻结的 PPI 上点击角反的原始雷达点。系统显示并保存精确 `x/y/z`、距离、速度、功率和原始点索引；不使用聚类中心代替原始点。
4. 在同一冻结相机图像上点击角反的固定视觉中心。系统把 CSS 显示坐标换算为原始相机像素 `u/v`，处理画布缩放和留边。
5. 选择样本组：`fit` 或 `validation`，检查两侧选点后保存。每条样本带快照、时间、点位、像素、用户备注和采集顺序。
6. 在会话开始时填写或确认物理安装差，记录测量基准与不确定度；允许留空，但不允许把该项误称为已验证外参。
7. 移动并静置角反，重复采集。拟合组覆盖画面左/中/右及近/中/远；验证组必须是未参与拟合的独立位置。
8. 导出会话包。PC 求解器只用 `fit` 样本解算外参，再仅使用 `validation` 样本生成独立误差报告，并与物理安装差作合理性比较。
9. 操作者审阅误差、样本覆盖度和机械残差。仅在确认合格后，手动将生成 JSON 配置为服务的 `--camera-calibration` 参数并重启服务。

## 数据模型与边界

会话是浏览器持有的可导出 JSON，包含以下字段：

```json
{
  "schema_version": 1,
  "camera_image_size": [1280, 720],
  "mount_measurement": {
    "camera_center_in_radar_m": {"dx": 0.0, "dy": 0.0, "dz": -0.1},
    "camera_yaw_pitch_roll_deg": {"yaw": 0.0, "pitch": 0.0, "roll": 0.0},
    "uncertainty_m": 0.005,
    "reference": "radar phase centre to camera optical centre",
    "axis_verification": "raised reflector test pending"
  },
  "samples": [
    {
      "id": "sample-001",
      "set": "fit",
      "radar": {"frame_num": 32351, "x": 0.694, "y": 0.175, "z": -0.725, "point_index": 4},
      "camera": {"frame_id": 5710, "u": 640.0, "v": 360.0},
      "sync_offset_ms": 12.2,
      "captured_at": "2026-09-23T00:00:00Z",
      "note": "3 m, centre"
    }
  ]
}
```

会话数据只用于生成标定候选，不触发服务重载，也不会自动开启视频投影。页面必须清晰显示：没有有效相机内参、少于六个拟合样本、少于一个验证样本、相机帧未匹配或点位未完整选择时，均不能导出“可求解”数据。

## 求解与验收

`tools/fusion/calibrate_radar_camera.py` 接受会话包或等价 CSV：

- 仅 `fit` 组参与 `solvePnP`；至少 6 组，推荐 12–20 组。
- `validation` 组不参与求解；至少 1 组，推荐 6–10 组。
- 输出分别报告拟合 RMS 与独立验证的 median、P95、最大误差和样本数。
- 输出 `camera_center_in_radar_m`，并在输入了安装测量时报告各轴的测量残差；`translation_m` 同时保留为投影使用的相机坐标量。
- 验收目标：独立验证 median 不大于 8 px、P95 不大于 20 px。未达到门限时不生成可部署标定文件。
- 输出仍使用现有 `RadarCameraCalibration` JSON 架构，因而可由已有投影链加载。

## 错误处理与安全行为

- 快照后的实时帧不能修改快照中的点、图像或时间偏移。
- 选择点不在图像可视区域、雷达点为空、画布点击超出图像内容区域时，拒绝保存并给出可操作提示。
- 删除样本必须可见且可撤销到会话当前状态；导出前显示样本表和组别计数。
- 安装测量值必须为有限数；填写的 `dz` 明确说明“相机相对雷达向上为正”，并显示用户示例的雷达高于相机 10 cm 对应 `-0.10 m`。
- 不以 SNR TLV 为前提，因为当前帧可能没有 SNR TLV；仍保留原始可用功率/侧信息作复核。
- 所有服务器端硬件适配、雷达串口、相机采集和云台控制保持现有行为；本功能只读取已经通过 WebSocket 到达浏览器的数据。

## 测试与分阶段验收

1. 纯前端单元/静态测试：快照完整性、CSS 到原始像素坐标转换、样本完整性和组别计数。
2. 浏览器模拟测试：模拟 `matched` 帧，选择雷达点和图像像素，保存 fit/validation 样本，验证实时后续帧不会改变保存的数据。
3. PC 求解器测试：合成已知外参数据，证明 validation 误差独立于 fit 样本计算；遗漏内参、拟合样本或验证样本均安全失败。
4. 真实设备手动验收：固定雷达和相机，使用 5 cm 角反采集独立位置；保存会话、在 PC 生成候选结果、检查独立误差，再由操作者决定是否部署。

本设计中的本地测试与浏览器模拟不能替代第 4 项真实硬件验收。
