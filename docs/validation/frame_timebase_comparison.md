# 旋转 PPI 方位时间轴离线对照

运行（只读采集，不连接设备）：

```powershell
python tools/analyze_scan_timing.py docs/linux/capture_20261112_120633_停转/frames.jsonl --metadata docs/linux/capture_20261112_120633_停转/metadata.json --rpm 30.1
```

目录名“停转”是误标；这组实际为旋转采集。`--rpm` 是本次约 30.1 rpm 的角度预算输入，不由工具从雷达推算。工具从采集的 `active_config.content` 中读取唯一生效的 `frameCfg`，忽略注释行。比较的是主机解包间隔与“连续帧号 × CFG 计划周期”；**后者是估计时间，不是 RF 采集时间，也未标定相对编码器的固定延迟**。它不能直接替换在线配准时间戳。

本组 752 帧（10 ms CFG）帧号无缺失；主机相邻间隔最大 37.66 ms，88 次超过 20 ms，184 次短于 5 ms。按 30.1 rpm 换算，主机间隔有 81 次大于 5°，最大约 6.80°；帧号计划时间最大 1.806°，没有大于 5° 的间隔。主机与帧号时间的相对残差范围约 35.57 ms。这支持“串口成批到达/主机解包时刻造成方位跳变”的假说，但不排除编码器查询延迟、绝对时间偏移和绘图质量门共同影响。

如果黑区连外圈采样刻度也缺，说明该方位未落入有效 TLV2 方位线，不应解释成单纯回波弱。网页继续保留这些扇区，不靠加粗、插值补满。板端 `device_time_cpu_cycles` 在本组为 0，尚无 RF 时间戳校准证据。

## 直接回放实时组装器

```powershell
python -m tools.replay_scan_timebases 'docs/linux/capture_20261112_120633_停转' --live-assembler
```

普通离线对照用整段数据的中位残差对齐时标；这个选项从采集起点新建两个实时 `LiveScanAssembler`，按主机解包与编码器查询完成时间近似重建事件到达顺序。试验臂使用首个到达帧作为时标起点，并受实时历史角度、质量检查和跨圈迟到限制。工具核对原始包与帧索引，仅将可解码、非空且在实时支持格数内的 TLV2 算作方位线；不渲染回波像素，也不验证目标绝对方位。结束时仍在等待编码器样本的帧单列为 `unresolved_at_capture_end`。

实时回放要求录制正常完成，帧索引和编码器日志计数与元数据一致、记录器未丢这两类数据、原始 CFG 快照 SHA-256 一致，以及录制开始时转台和配准均处于启用状态、编码器方向已验证。记录器丢失与真实帧号缺口是两件事：前者拒绝作为此对照的输入，后者照常统计、不补线。

同一份采集的 752 帧均含 TLV2，帧号无缺失：

| 完整圈 | 主机时标：有效线 / 最大角间隔 | 试验时标：有效线 / 最大角间隔 |
| --- | ---: | ---: |
| 1 | 202 / 6.80° | 203 / 1.94° |
| 2 | 201 / 6.72° | 201 / 1.92° |
| 3 | 202 / 6.48° | 201 / 1.92° |

另一组 11 月 9 日漏线采集（586 帧均有可解码 TLV2、帧号无缺失）也复现了改善：三个完整圈的最大角间隔从 8.13° / 7.95° / 6.93° 降到 2.92° / 2.57° / 3.06°。试验时标仍有 5 帧无有效编码器区间、1 帧在采集结束时待定；有效配准总数从 582 降至 580。缺口缩小不代表接收帧数或有效线数增加。

### 同一条 TLV2 换时标后移动了多少

实时组装器回放现在默认在 `relative_yaw` 输出统计；追加 `--per-frame` 查看每条匹配的帧号、原始主机时间、两种方位和带符号角差。仅比较两边都成功配准且 TLV2 可解码的同一帧，按原始帧号和主机时间匹配。角差定义为“试验时标方位 − 主机时标方位”，折回 `[-180°, 180°)`；一边或两边未配准单列计数，不当成 0°。P95 指 95% 的匹配帧不超过的绝对变化（取最近秩）。

| 实际旋转采集 | 匹配 TLV2 | 带符号中位数 | 绝对变化 P95 | 最大绝对变化 |
| --- | ---: | ---: | ---: | ---: |
| 11 月 9 日 | 580 / 586 | +0.51° | 2.67° | 4.26° |
| 11 月 12 日 | 748 / 752 | −0.30° | 4.02° | 4.95° |

两组中位数方向相反，但局部差异可达数度。结果不支持从这两组直接选一个统一的方位补偿；也不能把两种估计结果的差当成对真值的误差。现场固定角反和实时运行验证仍需独立完成。

下一次现场按 README 做 A/B：固定一个已知方位的角反，保持 CFG、转速、方向和安装参数不变，每组至少采三个完整圈。对比 `turn_diagnostics.jsonl` 的逐圈最大缺口、有效线、拒绝原因，再用角反核对两组目标方位与实测参考。缺口变小只证明采样分布更均匀；若固定目标产生不可接受的偏移，保持默认主机时标，不用扩大显示扇区掩盖问题。

## 现场 A/B 采集的离线判读

这一步不要求分析电脑接入设备。等可上电时，由操作员在转速稳定、编码器方向已验证后分别录制：A 为默认主机时标，B 为试验帧号时标。保持同一 CFG、转速、方向、零位、安装角和角反位置。每组多录一圈留给边缘裁剪，例如 30 rpm 下稳定录约 12 秒；实际以至少三个可核对的完整圈为准。测量雷达到角反的斜距，以及角反相对 PPI 零位的方位（正上为 0°、顺时针为正）。保留原始采集目录的 `metadata.json`、`frames.jsonl`、`frames.tlv`、`motor_samples.jsonl`、`live_registration.jsonl`、`turn_diagnostics.jsonl`。

```powershell
python -m tools.compare_field_ppi 'A_主机时标采集目录' 'B_帧号试验采集目录' --range-m 2.0 --azimuth-deg 0 --range-gate-m 0.2 --azimuth-gate-deg 20 --min-contrast 100
```

命令中的距离、角度和对比度是示例，按实际调查替换，两个采集共用同样的搜索参数。对比度是目标距离窗里的峰值减附近距离格的中位背景，单位是原始 TLV2 数值（不是 dB，也不是 SNR）。报告输出 JSON 到终端，不写原始采集。旧采集没有日志内的实际 A/B 时标和逐圈记录，仍用上一节的回放工具，不能当现场验收输入。

- `max_gap_change_deg`：B 减 A 的最坏整圈间隔；负值表示缩小。逐圈原始帧缺号、TLV2 缺失、配准拒绝分别保留。
- `target_bias_change_deg`：B 减 A 的角反**候选峰**相对实测方位的中位角差，已处理跨 0°。同时看两组各自的绝对偏差、候选圈数和圈间分散，避免“两组都偏同样多”被误判为准确。
- `null` 表示未判定，例如有效圈少于 3、够强的候选峰少于 3 圈、或两组实测转速中位数相差超过 5%。目标峰可能来自其他反射；不明确时可再录同条件无角反对照或换一个已测方位，不能用门限把目标偏移掩盖掉。
