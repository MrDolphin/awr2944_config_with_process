# 旋转 PPI 方位时间轴离线对照

运行（只读采集，不连接设备）：

```powershell
python tools/analyze_scan_timing.py docs/linux/capture_20261112_120633_停转/frames.jsonl --metadata docs/linux/capture_20261112_120633_停转/metadata.json --rpm 30.1
```

目录名“停转”是误标；这组实际为旋转采集。`--rpm` 是本次约 30.1 rpm 的角度预算输入，不由工具从雷达推算。工具从采集的 `active_config.content` 中读取唯一生效的 `frameCfg`，忽略注释行。比较的是主机解包间隔与“连续帧号 × CFG 计划周期”；**后者是估计时间，不是 RF 采集时间，也未标定相对编码器的固定延迟**。它不能直接替换在线配准时间戳。

本组 752 帧（10 ms CFG）帧号无缺失；主机相邻间隔最大 37.66 ms，88 次超过 20 ms，184 次短于 5 ms。按 30.1 rpm 换算，主机间隔有 81 次大于 5°，最大约 6.80°；帧号计划时间最大 1.806°，没有大于 5° 的间隔。主机与帧号时间的相对残差范围约 35.57 ms。这支持“串口成批到达/主机解包时刻造成方位跳变”的假说，但不排除编码器查询延迟、绝对时间偏移和绘图质量门共同影响。

如果黑区连外圈采样刻度也缺，说明该方位未落入有效 TLV2 方位线，不应解释成单纯回波弱。网页应继续把这些扇区留白；不要靠加粗、插值补满。下一步需记录或标定雷达帧与编码器的时间偏移，并在同一采集上重放对比逐圈有效线数、最大缺口和固定目标方位，再决定是否把估计时间轴作为可切换的试验模式。板端 `device_time_cpu_cycles` 在本组为 0，尚无 RF 时间戳校准证据。
