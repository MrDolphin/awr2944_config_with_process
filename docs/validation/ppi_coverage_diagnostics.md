# PPI 方位覆盖诊断与后续计划

## 本阶段：滚动窗口诊断（2026-11-07）

有界扇形显示已经在 f1dc6d1 完成。本阶段只增加可观测性，不更改 CFG、拒绝阈值、串口时序、电机或设备安全参数。

服务端 `live_registration.coverage` 随现有 WebSocket 状态发送：

| 字段 | 定义 |
| --- | --- |
| window | `rolling_360_deg`：最近实测累计转角 360° 内仍保留的 TLV2，不是固定零位分圈报告 |
| phase | `collecting` 首圈采集中；`rolling` 连续有效编码器运动已达一圈；`stale` 编码器过期。rolling 不代表无丢帧或全覆盖 |
| observed_travel_deg | 自本次地图清空后，连续有效编码器区间累计转角 |
| valid_spokes | 窗口中通过配准、具有有效 TLV2 的线数；同角重复采样仍计数 |
| unique_azimuths | 按角度归一化至 [0,360)，四舍五入到小数点后 6 位后去重；数值去重精度不是测角精度 |
| max_gap_deg | 上述方位排序后最大相邻圆周角间隔，包含跨 0° 间隔；空数据为 null，单一方位为 360° |
| capacity_limited | 当前窗口中是否有因方位缓存容量而被提前移出的数据；不是串口丢帧判断 |

`rejected_frames` 保留原字段以兼容；网页明确称“累计拒绝事件”，自配准器重置累计，包含帧拒绝及编码器非单调时间异常，**不是本圈丢帧数**。悬停诊断文字可查看原因计数。

最大角间隔不是天线未照射角，也不是画面黑色扇区宽度。显示单元会延伸半个正常间隔，不能据此改变采样统计。

## 网页如何判断缺口

在“TLV2 强度 PPI”工具区域查看诊断，不覆盖雷达图。

- 外圈灰蓝色短刻度只表示网页实际保留的方位样本，与背景抑制、亮度、目标检出无关。
- 外圈有刻度但内侧黑：有样本但显示回波较弱/被抑制，不能直接判定无目标。
- 外圈没有刻度：网页该处没有保留的样本。进一步结合服务端最大角间隔、容量提示和拒绝原因区分来源；仍不能只凭截图定位串口或编码器故障。
- 服务端有效线数与网页显示线数可能因增量传输暂时不同，两个值不可混当作帧率。
- 首圈未转完时最大角间隔很大是预期行为；静止重复采样不会伪装为整圈覆盖。
- 旧服务端或配准未启用时显示“诊断未提供”，不伪报零缺口。

3. 首圈观察 `首圈采集中`，一圈后观察 `滚动最近360°`。记录服务端有效线数、独立方位、最大角间隔、网页线数、拒绝事件增量及容量提示。
4. 调整显示亮度/抑制，观察外圈刻度位置不随强度变暗而消失。此步骤仅验证显示，不验证检测率。
5. 对大缺口同时保存采集与服务日志；对照 TLV 帧号、时间戳、编码器前后样本、配准拒绝原因，不先放松阈值。
6. 30 rpm / 10 ms 的计划角间隔为 1.8°、约 200 帧/圈；只有实际计数接近且缺口可解释，才报告实测有效线数。不要把理论值写成实测值。
